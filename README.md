Le code complet de l’application Radar est à la racine. Le dossier PASSATION contient la synthèse et les fichiers issus de la Bibliothèque du projet, notamment les fiches d’analyse, rapports, captures, propositions HTML, prototypes et visuels.

Les 61 sources logiques sont réunies dans PASSATION/sources, pour 88 188 473 octets. L’aperçu HTML de 16,9 Mo est séparé en quatre fichiers pour respecter la limite de téléversement web de GitHub : réunir les parties Vrai-Consulting-apercu.html.part-01 à .part-04 dans cet ordre pour reconstruire le fichier. Le dépôt contient donc 64 fichiers physiques. La présence d’un prototype ou d’une proposition ne prouve pas qu’un site a été validé, livré ou installé chez l’entreprise.

## Limite importante

Le navigateur connecté ne contenait pas de session du Radar Rework. L’export actuel de l’onglet privé « Sites réalisés » n’a donc pas pu être récupéré. CURRENT_STATE.md décrit le fonctionnement de cet onglet au 24 septembre, mais ne contient pas les cartes ni leur liste nominative. L’inventaire des sites est donc historique et doit être rapproché d’un export récent du Radar avant de le considérer complet.

## Règles de travail à respecter

Les notes du dossier séparent les faits observés, les hypothèses, les décisions de Romain et les propositions de l’assistant. Ne pas contacter une entreprise, modifier un site client ou déclencher une génération. Le workflow de refonte requiert deux validations explicites : la direction artistique, puis le prototype d’ouverture.

Ce dépôt a été préparé pour une transmission ponctuelle. Romain a demandé qu’il soit public pendant la passation puis remis en privé après récupération des éléments.
